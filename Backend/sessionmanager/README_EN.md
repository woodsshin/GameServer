# sessionmanager

A Go microservice that acts as the session/progress store for the Icarus backend. It stores and retrieves in-game loadouts, ongoing match (Prospect) state, and tracked stats sent by game clients, using a Redis cluster, and communicates asynchronously with other services via RabbitMQ.

## Overview

- **Role**: A state-storage layer responsible for "what this character is currently carrying, which match (Prospect) it's in, and who the host is." It's referenced both by client requests arriving via the Gateway and by RPC requests from other backend services such as the Player Service.
- **Communication**: Asynchronous request/response via the RabbitMQ (AMQP) message broker.
- **Data store**: Redis Cluster (`go-redis/v8`)
- **Health check**: Exposes a separate `/health` HTTP endpoint.

## Architecture

```
┌────────────┐   MM Exchange     ┌──────────────────┐    HGet/HSet/Pipeline    ┌───────────────┐
│  Gateway /  │ ────────────────▶ │                   │ ───────────────────────▶│               │
│  Other      │   (RabbitMQ)      │  sessionmanager    │                          │ Redis Cluster │
│  services   │ ◀──────────────── │  (SM Exchange)     │                          │               │
└────────────┘   Response         └──────────────────┘                          └───────────────┘
                (QueueMessage)
```

- Declares and binds the `SM` exchange/queue, consumes messages, processes them, and sends the response back to the `queueName` included in the request.
- Copies the `frameidx` header through unchanged from request to response, allowing the calling service (e.g. `adminproxy`-type services) to correlate an asynchronous response back to its original request.
- If the connection drops, `rabbitConnector` reconnects by redeclaring the exchange/queue/binding from scratch (maintaining state consistency even across a broker restart).

## Events Handled

Events registered in the code-generated handler registry (`handler_gen.go`).

| Event | Description |
|---|---|
| `ReqGetCharacterLoadout` / `ReqUpdateCharacterLoadout` | Look up/save the in-game loadout (gear, backpack, quickbar configuration) per character slot |
| `ReqUpdateTrackedStats` | Save tracked stats accumulated during a Prospect |
| `ReqGetAllProspects` / `ReqGetProspect` / `ReqUpdateProspect` | List ongoing matches (Prospects), fetch a single one, and update its state (elapsed time, actor blob, etc.) |
| `ReqResumeProspect` | Resume game state on session reconnection, after reassigning the host and handling the lock |
| `ReqHostCandidate` | Register a host-migration candidate |
| `ReqBackToHab` | Reflect progress when returning to the home base (Hab) after a Prospect ends |

## Key Design

### 1. Code-Generated Three-Layer Handler Structure
- `handler_gen.go` — Auto-generates, from a schema, the mapping between event names and handler functions along with request deserialization/response serialization logic. It handles only the signatures and dispatch code, delegating the actual logic to a separate file.
- `handler_impl.go` — A hand-written layer containing the actual business logic (the `on*Impl` functions), preserved across regenerations of the generated code.
- `handler_custom.go` — An extension point for exceptional registrations/overrides not covered by the generator (currently an empty hook).

The key idea behind this structure is that when request/response schemas change, the dispatch and (de)serialization code can be regenerated by the code generator without affecting the hand-written business logic layer.

### 2. Redis Hash-Based State Model
- Character state key: fields such as `bHost`, `joinedProspect`, and `loadout` (JSON-serialized) are stored in a hash keyed as `{userID}_{chrSlot}`.
- Prospect state key: fields such as `hostID`, `hostUpdatedTime`, `isExpired`, `elapsedTime`, and compressed actor blobs (`actorsData`, `actorsHash`, etc.) are stored in a hash keyed as `{prospectID}`.
- Every update groups the relevant fields into a single transaction via `TxPipeline`, and `context.WithTimeout` guards against round-trip delays to Redis.

```go
// GetCharacterLoadout ...
func GetCharacterLoadout(request model.ReqGetCharacterLoadout) (model.ResGetCharacterLoadout, error) {
	var resLoadout model.ResGetCharacterLoadout

	userChrKey := fmt.Sprintf("%v_%v", request.UserID, request.ChrSlot)

	bLoadoutVal, err := client.HGet(ctx, userChrKey, "loadout").Result()
	if err != nil {
		if err == redis.Nil {
			return model.ResGetCharacterLoadout{Loadout: model.CharacterLoadout{Valid: true}}, nil
		}
		return model.ResGetCharacterLoadout{Loadout: model.CharacterLoadout{Valid: false}}, errors.New("Not available loadout")
	}

	err = json.Unmarshal([]byte(bLoadoutVal), &resLoadout.Loadout)
	if err != nil {
		return model.ResGetCharacterLoadout{Loadout: model.CharacterLoadout{Valid: false}}, errors.New("Invalid loadout")
	}

	return resLoadout, nil
}

// UpdateCharacterLoadout ...
func UpdateCharacterLoadout(socketID string, request model.ReqUpdateCharacterLoadout) error {
	if socketID != request.UserID {
		return errors.New("Invalid userId")
	}

	bLoadout, err := json.Marshal(request.Loadout)
	if err != nil {
		return errors.New("Invalid loadout")
	}

	userChrKey := fmt.Sprintf("%v_%v", request.UserID, request.ChrSlot)

	err = client.HSet(ctx, userChrKey, "loadout", bLoadout).Err()
	if err != nil {
		return errors.New("Failed to update loadout")
	}
	return nil
}
```

The path that updates Prospect state needs to apply several fields at once, so it uses `TxPipeline`:

```go
pipe := client.TxPipeline()

// ... after validation ...

pipe.HSet(ctx, prospectID,
    "hostUpdatedTime", updatedTime,
    "lastClientUpdatedTime", updateProspect.UpdateTime,
)

timeout, cancel := context.WithTimeout(context.Background(), 1*time.Second)
defer cancel()
_, err = pipe.Exec(timeout)

if ctx.Err() == context.Canceled || ctx.Err() == context.DeadlineExceeded {
    return ctx.Err(), model.UpdateProspectFailure_UndefinedID
}
```

### 3. Concurrency Control for Host Migration / Reconnection
- `ResumeProspect` uses an `HSetNX`-based distributed lock (`{prospectID}_lock`) to ensure only one of several concurrent reconnection requests enters the critical section, with a TTL (`Expire`) guaranteeing the lock is never left dangling permanently.
- If more than 30 seconds have passed since the last host update, another client is allowed to be promoted to host — a timeout-based failover that prevents the session from stalling if the host dies.
- If the `AttemptHostMigration` flag is set, only the user matching the previously registered `candidateID` may take over as host.

```go
// Try and get the lock to the DB, only one request can access the remainder of this call at a time
totalLockTime := 30
var timeSpentLocked int
lockKey := request.ProspectID + "_" + "lock"
for {
	lockSet, err := client.HSetNX(timeout, lockKey, "locked", true).Result()
	if err != nil {
		return response, err
	}
	if lockSet {
		break
	}

	time.Sleep(1 * time.Second)
	timeSpentLocked++
	if timeSpentLocked > totalLockTime {
		return response, errors.New("failed to get lock on redis")
	}
}

err := client.Expire(ctx, lockKey, time.Duration(totalLockTime)*time.Second).Err()
defer func() { client.HDel(ctx, lockKey, "locked") }()
```

Once the lock is acquired, the target for host promotion is determined by the elapsed time since the last host update, along with whether the user is a registered host-migration candidate:

```go
// Allow a new host to take over if the timeSinceLastUpdate is above a certain threshold
timeSinceLastUpdate := updatedTime - hostUpdatedTime
shouldHost := response.HostID == socketID || timeSinceLastUpdate >= 30

// Check if the user is the host candidate and is trying to migrate host
if request.AttemptHostMigration {
	candidateID, _ = client.HGet(ctx, request.ProspectID, "candidateID").Result()
	shouldHost = candidateID == socketID
}
```

### 4. Data Integrity Verification
- In `UpdateProspect`, the compressed actor blob sent by the client is decompressed via `zlib`, its SHA-1 hash is recomputed, and that's checked against the hash included in the request — preventing state data that was corrupted or tampered with in transit from being stored.
- Comparing against `lastClientUpdatedTime` discards stale update requests, preventing an out-of-order message from overwriting more recent state.

```go
if updateProspect.HasProspectBlob {
	blob, err := compress.Unzip(updateProspect.ProspectBlob.BinaryBlob)
	if err != nil {
		return errors.New("failed to decompress data"), model.UpdateProspectFailure_Other
	}

	hash := sha1.New()
	hash.Write(blob)
	if hex.EncodeToString(hash.Sum(nil)) != updateProspect.ProspectBlob.Hash {
		return errors.New("hashes do not match"), model.UpdateProspectFailure_Other
	}
	// ... only stored via pipe.HSet if validation passes ...
}
```

The part that filters out stale requests looks like this:

```go
lastClientUpdatedTimeVal, err := client.HGet(ctx, prospectID, "lastClientUpdatedTime").Result()
if err == nil {
	lastClientUpdatedTime, _ := strconv.ParseInt(lastClientUpdatedTimeVal, 0, 64)
	if lastClientUpdatedTime >= updateProspect.UpdateTime {
		return nil, model.UpdateProspectFailure_NotNewer
	}
}
```

## Tech Stack

- **Language**: Go
- **Messaging**: RabbitMQ (`streadway/amqp`), `SM` exchange
- **Storage**: Redis Cluster (`go-redis/v8`), hash-based schema, client-side pipelining
- **Compression/Integrity**: zlib compression (`compress/zlib`), SHA-1 hash verification
- **Web**: `gorilla/mux` (for the health-check endpoint only)
- **Serialization**: `encoding/json`

## Design Points

- **Message-broker-based asynchronous RPC**: All requests and responses travel as RabbitMQ messages, implementing request-response pairing on top of the asynchronous pub/sub model via the `frameidx` correlation header.
- **Distributed lock + timeout-based single-host guarantee**: Combines a Redis lock with time-based failover so that multiple clients in a distributed environment can never simultaneously claim host authority.
- **Code-generation-based maintainability**: Even as event schemas are added or changed, regenerating `handler_gen.go`/`model_gen.go` alone is enough to update the dispatch/serialization layer, while the business logic (`handler_impl.go`) stays safely isolated from regeneration.
